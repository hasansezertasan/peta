# Design: Migrate real implementation into `peta`

- **Date:** 2026-08-03
- **Branch:** `feat/migrate-source` (off the clean `copier-pyproject` baseline)
- **Status:** Approved design — pending implementation plan

## Summary

`peta` was scaffolded from the `copier-pyproject` template as a layered skeleton
(placeholder `core/app`, `core/config`, `core/dirs`, `core/logging_setup`, `utils/`,
a Textual `tui/`, and a two-command Typer CLI). The real implementation of `peta` —
a **human-friendly Python package metadata viewer** ("`cargo info` for Python") —
lives in a separate internal reference. This migration replaces the template
skeleton with that real implementation, conformed to the template's strict tooling
standards, and re-documents the project under Document-Driven Development.

The source is migrated from an internal reference implementation. Its repository
name and URL are deliberately omitted from this codebase.

## Goals

- Replace the skeleton `src/peta/**` with the real 3-layer implementation.
- Conform migrated code to the scaffold's strict gates (ruff `ALL`, mypy strict,
  basedpyright, cyclomatic complexity ≤ 5, coverage `fail_under = 99`).
- Move runtime dependencies (`typer`, `rich`, `httpx`, `packaging`) into
  `[project].dependencies`; drop the scaffold's `cli`/`tui`/`all` extras.
- Fix the entry point to `peta = "peta.cli.app:run"`.
- Pin `requires-python = ">=3.14"` (peta is an end-user tool run via uvx/pipx/brew,
  which bundle their own interpreter).
- Preserve dynamic versioning (hatch-vcs from git tags) + release-please — no
  hard-coded version literal anywhere.
- Document **reality only** (the 4 implemented commands), first, as the contract.
- Organize tests into `smoke/ unit/ integration/ e2e/` tiers.

## Non-goals (explicitly dropped)

The reference README over-promised relative to its code. The following are **not**
migrated (YAGNI — "document reality only"):

- `compare` command; `deps --why`; recursive dependency trees; OSV vulnerability
  source; download/dependent counts; `--no-color` flag.
- The unused `DependencyNode` model and the never-populated `download_count` /
  `dependent_count` fields on `PackageInfo`.
- The reference's `ALTERNATIVES.md`, `DEVELOPMENT.md`, `adr/`, `research/` docs
  (the scaffold's `CONTRIBUTING.md` already covers development).

## Component contracts

| Unit | Responsibility | Depends on | Public API |
|------|----------------|-----------|-----------|
| `core/models.py` | Data shapes | `dataclasses` | `PackageInfo`, `Vulnerability` |
| `core/local.py` | Read installed pkg metadata | `importlib.metadata`, models | `get_package(name) -> PackageInfo`; `PackageNotFoundError` |
| `core/remote.py` | PyPI JSON fetch | `httpx`, models | `get_package(name, version=None)`; `PackageNotFoundError`; `NetworkError`; `PYPI_BASE_URL`; `DEFAULT_TIMEOUT` |
| `output/tables.py` | Rich → string | `rich`, models | `render_info/deps/files/versions(...)` |
| `output/json.py` | JSON → string | `json`, models | `format_info/deps/files/versions(...)` |
| `cli/commands/*.py` | Orchestrate resolve → render | core + output | `info/deps/files/versions(...)` |
| `cli/app.py` | Typer wiring, arg parsing, entry | typer, commands | `app`, `run` |

Each unit is understandable and testable in isolation; consumers depend only on the
listed public API.

### Version wiring (key integration point)

The reference hard-coded `__version__ = "0.1.0"` in `__init__.py`. Under hatch-vcs:

- `_version.py` is generated with `__version__` + `version` from the git tag.
- `src/peta/__init__.py` re-exports: `from peta._version import __version__`.
- `cli/app.py`'s `_version_callback` keeps `from peta import __version__`, now
  resolving dynamically. **No version literal is committed anywhere.**

### Complexity conformance

`core/local.get_package` and `core/remote.get_package` do heavy inline parsing.
To satisfy complexity ≤ 5, extract pure private helpers (e.g. `_parse_project_urls`,
`_parse_keywords`, `_build_package_info`) — behavior identical, each testable.

## Data flow

```
peta <pkg>            → run() injects "info" → info command
peta info <pkg>       → _resolve_package():
    name==version     → remote(name, version)
    --remote/-r       → remote(name)
    --local/-l        → local(name)
    (default)         → try local(name); on LocalNotFound → remote(name)
peta files <pkg>      → local only
peta versions <pkg>   → remote only (PyPI /json releases, sorted desc via packaging.Version)
```

Then `--json` → `output.json.format_*`, else `output.tables.render_*`; handler
`typer.echo`s the result.

## Error taxonomy & exit codes

| Condition | Exception | Exit | stderr |
|-----------|-----------|------|--------|
| Not found (local or remote) | `PackageNotFoundError` | 1 | `Package '<x>' not found.` |
| `files` not installed locally | `LocalNotFound` | 1 | `Package '<x>' not found locally.` |
| Network / HTTP failure | `NetworkError` | 2 | `Network error: <detail>` |
| `--version` | — | 0 | `peta <version>` |

**Full-conformance fixes:** add `from e` / `from None` to every re-raise inside an
`except` (B904); narrow the reference's bare `except Exception` around `httpx.get`
to `except httpx.RequestError` (BLE001); annotate `importlib.metadata` accesses so
`PackageInfo(...)` construction is fully typed under mypy-strict / basedpyright.

## Testing (tiered)

```
tests/
  conftest.py                   # shared PackageInfo factory fixtures
  smoke/
    test_smoke.py               # import peta; __version__ resolves; `peta --version` exit 0
  unit/                         # pure logic, fully mocked — no I/O, no network
    test_models.py
    test_local.py               # mock importlib.metadata.distribution
    test_remote.py              # mock httpx.get
    test_output_tables.py
    test_output_json.py
    test_cli.py                 # CliRunner, core mocked; routing + exit codes
  integration/                  # real components wired, no external network
    test_local_real.py          # core.local against a really-installed dist (e.g. typer)
    test_pipeline.py            # resolve → render, mocked only at the httpx boundary
  e2e/                          # full CLI via the real entry point
    test_cli_local.py           # `peta info/files <installed>`, `peta <pkg>` — deterministic, no network
    test_cli_remote.py          # hits real PyPI — @pytest.mark.e2e, opt-in / skippable
```

- Register markers `smoke`, `unit`, `integration`, `e2e` in
  `[tool.pytest.ini_options].markers`; each dir carries `__init__.py`.
- `smoke + unit + integration` must reach **real 99%** offline — the gated coverage
  run has no network dependency. No `# pragma: no cover` to fake coverage (only the
  scaffold's already-whitelisted `if __name__` guards).
- `e2e/test_cli_remote.py` is opt-in (marker-gated / network-flagged) so CI coverage
  never depends on PyPI reachability.
- Drop skeleton tests (`test_config`, `test_logging_setup`, `test_main`, `tui/`,
  `cli/test_app.py`).
